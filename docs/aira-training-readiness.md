# AIra-v2 base training readiness

Status: 2026-08-21. This document is the handoff contract between dataset collection and the first event-model training gate. The canonical architecture/evidence remains in [`aira-v2-audit.md`](aira-v2-audit.md).

## What is now implemented before data arrives

1. **Lossless event packer** (`aira/events.py`)
   - bounded literal byte patches;
   - statistically gated shelf-copy spans;
   - exact prompt/retrieval source-copy spans with source ID and offset;
   - lossless reconstruction and checksums;
   - separate event-sequence and neural-invocation upper-bound accounting.
2. **Multi-byte event core** (`MultiByteEventLM`)
   - 1–8 byte literal heads;
   - learned continuation/stop decisions;
   - categorical route head for literal, shelf copy, source copy, memory and tools;
   - masked proper losses so deterministic copy payloads are not incorrectly trained as neural literals.
3. **Real sampled residual objective** (`aira/residual.py`)
   - every surprise/event position is retained;
   - only a configurable random control stream of predictable positions is retained;
   - inverse-probability weighting preserves an unbiased estimate of dense full loss;
   - unlike low-weight dense loss, this can reduce actual backward examples.
4. **On-policy teacher contract** (`aira/on_policy.py`)
   - the teacher labels the exact prefix generated by the student, not the abandoned corpus continuation;
   - sparse Top-K logits and retained probability mass reuse the existing decoupled KL loss;
   - JSONL is hash-checked, teacher/student identified, atomic and pickle-free.
5. **Frozen experiment contract** (`configs/experiments/aira_event_pretrain_v1.json`)
   - local runs remain capped at 300 optimizer steps;
   - three seeds and matched controls are mandatory;
   - generated-context calibration is a hard deployment gate.
6. **Prepared-data and trainer path**
   - deterministic NPZ event shards with per-file hashes and tokenizer/source metadata;
   - hash-verified streaming shard reader;
   - multi-head event loss, non-finite guards and gradient clipping;
   - atomic checkpoints containing optimizer and exact Torch/NumPy RNG state;
   - resume rejects a changed config or event manifest.

## Measured packing upper bound on the current pilot

`results/aira_event_packing_proxy.json` packs 43,442 held-out UTF-8 bytes using a shelf built from about 2M training characters. These are lossless teacher-forced labels:

| packing rule | event compression | neural-invocation upper bound | copy fraction |
|---|---:|---:|---:|
| single literal byte | 1.00x | 1.00x | 0% |
| oracle 4-byte literal head | 4.00x | 4.00x | 0% |
| oracle 8-byte literal head | 8.00x | 8.00x | 0% |
| shelf + single byte | 1.02x | 1.03x | 3.17% shelf |
| shelf + 8-byte head | 7.15x | 7.88x | 3.17% shelf |
| shelf + prompt copy, minimum 2 bytes | 5.52x | 5.75x | 42.06% source |
| shelf + prompt copy, minimum 8 bytes | 7.25x | 7.81x | 2.32% shelf + 15.04% source |
| shelf + prompt copy, minimum 16 bytes | 7.24x | 7.97x | 3.08% shelf + 2.80% source |

The important result is negative as well as positive. Current shelf spans are short enough to fragment an 8-byte literal stream; they do not multiply the oracle 8x head. Very short prompt copies cover many bytes but increase event count. Even long source copies fail to exceed the pure oracle 8-byte event count once the same short shelf events remain enabled. Therefore the main unproved acceleration lever is a calibrated multi-byte head; copy actions currently improve exactness/provenance, not demonstrated speed.

`prepare_aira_event_data.py` and `train_aira_event_proxy.py` were executed end to end on a small frozen pilot. They produced deterministic event shards, trained the 4.68M-parameter configured core for five steps, validated it, saved a hash-bound checkpoint and resumed from step five to seven with config/dataset identity checks. `results/aira_event_training_smoke.json` records the initial smoke. This proves plumbing, not language quality.

## Synthetic SFT and mentor data

Synthetic chat datasets are not base-pretraining replacements. The first three user-proposed candidates are pinned and audited in [`aira-synthetic-sft-audit.md`](aira-synthetic-sft-audit.md), with machine status in `configs/corpus/aira_sft_candidates.json`. None is currently admitted to weights: two contain claimed Claude outputs with unresolved upstream service-term/provenance issues, and the third is repetitive imitation-of-imitation data.

The project-owned alternative is AI Babysit: student rollouts are verified, critiqued and corrected on their exact generated states. `aira/babysit.py` now provides hashed critique/correction/rubric/verifier/preference records; `aira/on_policy.py` stores sparse teacher distributions for the exact same prefixes. Teacher-service rights must still be checked before generated labels enter training.

The first owned seed, [`AIra Mentor v1`](aira-mentor-v1.md), is now materialized: 6,000 verifier-approved RU/EN conversations across arithmetic, algebra, logic, Python, tools, explicit memory, grounded QA, prompt injection, unknown rejection and critique/revision. It is only ~0.7M pilot-tokenizer tokens and must be used as later assistant-only SFT, never as a base-corpus substitute.

## Dataset handoff format

Preferred source format is one UTF-8 JSON object per line:

```json
{
  "document_id": "stable-source-local-id",
  "text": "document text",
  "language": "ru",
  "domain": "science",
  "source": "dataset/repository/revision",
  "license": "SPDX-or-explicit-license",
  "attribution": "required attribution",
  "split_group": "original-document-or-work-id"
}
```

Required properties:

- a stable source revision and SHA-256;
- explicit redistribution/training permission;
- document-level split group before chunking or packing;
- language and domain labels;
- no validation/test fragments in training derivatives;
- exact and near-duplicate audit;
- UTF-8 validity and original byte count;
- provenance retained through filtering;
- separate quarantines for uncertain license, PII and malformed records.

Do not combine train/validation/test in one undifferentiated text file. Do not accept a dataset solely because a model card says “open”; the underlying source license must permit the intended use.

## Initial mixture targets

These are starting audit targets, not forced sampling weights:

| Domain | Desired role |
|---|---|
| RU modern general/encyclopedic | core Russian capability |
| EN modern general/encyclopedic | core English capability |
| science/math | factual and structured reasoning |
| permissive code/JSON/configs | tools and deterministic formats |
| dialogue/instructions | later capability SFT, separate from raw base mix |
| public-domain literature | language breadth, capped to avoid style domination |
| tool traces | separately versioned procedural data |

The old 31M-token GitHub pilot remains a pipeline/control corpus. It is too small and narrow to claim a Gemma-level base.

## Teacher binding required before on-policy training

The teacher record must include:

- exact checkpoint/revision hash;
- tokenizer and serialization format;
- license/terms allowing generated training labels;
- Top-K width and temperature;
- deterministic prompt template;
- whether tools/retrieval were enabled;
- hardware/software environment;
- student checkpoint hash used to create each rollout.

A corpus target after a student-diverged prefix is invalid supervision. The teacher must evaluate that exact generated prefix and provide a fresh distribution or corrective action.

## First training matrix after dataset acceptance

All arms use identical data, seeds and parameter budget:

1. single-byte dense baseline;
2. 4-byte head without shelf;
3. 8-byte head without shelf;
4. 8-byte head plus shelf-copy events;
5. 8-byte head plus prompt/retrieval copy actions;
6. arm 5 plus importance-sampled predictable controls;
7. arm 6 plus on-policy Top-K teacher labels.

Primary metrics:

- normalized byte NLL/BPB;
- autonomous completion quality;
- event-state updates per output byte;
- neural invocations per output byte;
- active parameter bytes per output byte;
- measured CPU/GPU wall-clock;
- generated-context route precision/coverage;
- peak training memory and examples/second.

## Hard gates

No scaling beyond the local proxy unless:

- event sequence is at least 2x shorter;
- quality regression is no more than 2%;
- generated-context shelf/copy precision reaches at least 95%;
- autonomous neural calls fall by at least 20%;
- measured wall-clock improves by at least 1.5x after routing overhead;
- all results hold over at least three seeds.

Teacher-forced packing ratios and oracle copy spans are upper bounds, not speed claims.

## Remaining blockers outside dataset collection

- bind a legally usable strong teacher;
- implement a source-pointer head before training document-copy actions end to end;
- choose/freeze the tokenizer after the new corpus mixture audit;
- bind full-stream anchor batches and sampled residual controls into the large-data trainer recipe;
- produce a fused/incremental event runtime only after a safe generated threshold exists;
- scale the accepted 5M proxy through 20M and 50–100M controls before a serious base run.
